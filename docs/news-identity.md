## 識別規則

| 条件 | 動作 |
| --- | --- |
| 情報源と告知ID（RSS GUID・Atom IDなど）が一致 | 同一告知として更新する |
| URLが同じでも告知IDが異なる | 別の告知として保持する |
| 告知IDなし、またはIDがリンクURLそのもの | 情報源・URL・掲載日・正規化見出しの組で識別する |
| IDなしで見出しまたは掲載日が異なる | 別件として保持する。似ているだけで訂正と判断しない |
| 完全重複・比較用正規化だけの違い | 重複登録・訂正履歴の追加をしない |
| 同一取得内の同じIDに矛盾する見出し・URL・掲載日 | その情報源の更新を保留し、health.jsonへ理由を記録する |
| 同じ告知の重複行で非空カテゴリが矛盾 | その情報源の更新を保留する |
| GUIDが欠けた間に別候補が作られ、復帰後の訂正先と重なる | 手動の掲載判断や説明の参照IDを捨てて統合せず、更新を保留する |

URLの比較ではフラグメントだけを除く。パス、クエリ、末尾のスラッシュなどを勝手に同一視しない。見出しの比較にはNFKCと空白の整理を用いる。表示には取得した見出しを使う。

IDのある同一告知を更新するときは、掲載日・URL・カテゴリ・分類も更新する。掲載日が取得できなかった場合は既知の日付を維持する。新規告知で日付が不明ならnullのまま保存する。初回取得時刻と手動のpublish判断は維持する。見出し履歴は実質的な変更時だけ追加し、同じ過去見出しを繰り返し追加しない。

RSS/Atomでは告知IDを保存する。Atomはpublishedをupdatedより優先し、本文へのalternateリンクをselfやenclosureより優先する。

### 自動判定の限界

告知IDのない情報源で「誤字の訂正」と「よく似た別のお知らせ」を完全に区別することはできない。この変更は取りこぼしを避けて両方を保持するため、実際には訂正だった見出しが別項目として残る場合がある。

固有IDは発行元が同一告知へ安定して付けることを前提とする。同じ取得内のID再利用は検出するが、別々の取得時点で発行元がIDを別告知へ使い回した場合は、見出し訂正との区別を自動保証できない。曖昧な対応が検出された場合は自動統合せず、元の項目・掲載判断・説明を確認してから解消する。

## データ形式と移行

`data/items.json`のトップレベルに次の情報を保存する。

- `schema_version: 2`：この識別方式の形式。
- `items`：現行項目。`identity_key`は照合用SHA-256。新規の公開IDはその先頭20桁。旧IDを温存した行もあるため、公開IDをURLから再計算しない。
- `legacy_items`：別告知の混入を否定できない旧行を、全フィールド・全履歴込みで原形保存した配列。確定した記事一覧ではない。自動公開や保持期限削除の対象にしない。
- `shared_urls`：複数告知に使われたURL、および旧混在行のURL。項目が保持期限で消えた後も残す。

移行は情報源ごとの取得・検証が成功したときだけ行う。失敗した情報源の移行を途中まで保存しない。成功と失敗が混在するため、schema_versionが2でも未移行の情報源の行が残る場合がある。

1. 実質的な見出し変更履歴のない旧行は、公開ID・first_seen・publishを維持して識別キーを追加する。
2. 旧title_historyに異なる見出しが含まれる行は、元の内容をlegacy_itemsへ移す。旧履歴は正しい訂正履歴と仮定しない。
3. その時点の公式一覧で確認できた告知は、取得したID・見出し・掲載日に基づいて登録する。履歴の文字列を旧published付きの新記事へ展開しない。
4. 旧混在行が手動で非公開・要確認にされていたURLでは、新しい項目もreviewにする。自動で解除しない。
5. 同じ入力を再処理しても新規項目・隔離行・履歴を増やさない。

安全な旧行へ後からGUIDを追加する場合は、情報源・URL・掲載日・見出しが厳密に対応する1件だけに結び付け、公開IDを維持する。複数候補がある場合は保留する。

**PMHの医療費助成の見出しは、今回固定した現在のRSSには残っていない。legacy_itemsには保存されるが、現行の公開一覧には自動復帰しない。** 公表日・固有ID・内容を別の公式資料で確認する作業が必要。旧履歴だけから正確な日付を復元したと扱わない。

従来どおり現行itemsには120日（rules.jsonで指定）の保持期限を適用する。取得失敗時にも、保持期限処理と設定済み情報源の規則再分類は行う。一部の情報源だけを指定して試す場合は、指定外の情報源の既定分野を消さない。

## 説明と期限

説明は`item_id`と`url`を明示して対象を指定する。URLだけの旧形式は、非表示項目を含む全保存項目で一意であり、shared_urlsにもlegacy_itemsにもなく、指定の競合がないときだけ互換表示する。同じURLに別告知がある場合は、説明を全件へ複製しない。設定の重複・不明ID・URL不一致は標準エラーへ理由を出し、曖昧な説明を表示しない。

期限はもともと人が確認した独立の一覧で、itemsへ結合していない。取得処理・移行ではnotes.jsonとdeadlines.jsonの内容を書き換えず、期限を見出しから推定しない。登録方法は[運用の手引き](operations.md)を参照。
