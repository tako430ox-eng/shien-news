## 1. 何を「プロのやり方」とするか

実務の公的サービスの設計者が使っている、公開された基準を土台にする。好みや思いつきで見た目を決めず、**基準の出典 → 決まり → 自動で測る → 前後を見比べる → 本人が判断**の順で進める。

### 文字

| T1 | 文字の大きさは段だけ：14（札）・16（補足）・17（本文）・18（リード・h3）・22（h2）・28（h1）。641px 以上の画面では h3 20・h2 26・h1 36。`clamp()` などで中間の値を作らない | GOV.UK の段の考え方、デジタル庁の Std-17N-170 ほか |
| T2 | 14px 未満を使わない。補足でも 16px | デジタル庁 |

### アクセシビリティ（既存の決まりを引き継ぐ）

- 文字 4.5:1、部品の枠 3:1（`/mnt/project-files/design-system/check-contrast.js`）。
- 押せる部品 44px 以上（主な部品は 48px）。文中のリンクは除く。
- 暗い画面設定・印刷・強制カラーモード・動きを減らす設定で崩れない。
- 画面に固定する部品は、ほかの部品に重ねない。

## 3. 工程（新しいページ・直し・見直しのたびに）

1. **誰が・何をしに来るかを書く**：1〜2文で。困って来た人か、支える人か。スマホで、急いでいるか。
2. **中身の順番を決める**：緊急の案内 → 今日やること → 詳しい手順 → 窓口で言える文 → 出典。既存のページ（/shitsugyo/、/sasaeru/）の型を使う。
3. **既存の部品で組む**：`assets/site.css` の部品（.notice、.choose、.links .tool、.say、.today、.btn、.cta）だけを使う。足りないときは、この文書の決まりに合う部品を足し、この文書の「部品」の表にも書く。ページごとに独自の見た目を作らない。
4. **自動で測る**：
   ```
   python scripts/build.py --out site
   node scripts/design_audit.cjs site
   ```
   文字の大きさ・角の丸み・押せる大きさ・文節改行・はみ出し（390px・320px・320px で文字1.25倍）を測る。✗ が出たら直す。「最後の行が2字以下」は参考値（0 に近づける）。
5. **目で見比べる**：スマホ幅（390px と 320px）と PC 幅（1280px）で、変更前と変更後を撮って並べる。暗い画面設定も1枚。
6. **この文書の決まりで自己点検**：表の項目ごとに、合っているか、合っていないなら理由を PR に書く。
7. **PR にする**：前後の画像（または比較ページ）、`design_audit.cjs` の結果、テストの結果を付ける。テストと `design_audit.cjs` が通ったらマージして公開し、公開ページで確かめてコタローさんに報告する（2026-11-19、コタローさん「公開してよいかは毎回聞かなくていいです公開してください」。それまではマージ前に了承を取っていた）。

## 4. v1.2 → v2.0 で直したこと（2026-11-19 の点検結果）

点検は `scripts/design_audit.cjs` と、全7ページのスマホ・PC 幅の撮影で行った。

| 見つかった問題 | 基準 | v2.0 の直し |

## 5. 残っている課題

- **家賃編の最初の画面**：390×664・375×667・360×640 の画面では、4つのタイルが「すぐ閉じる」の帯より上に収まる（第2弾）。幅320px（320×568）と、文字を大きくする設定では収まらない。**これは受け入れる限界とする**（第3弾、2026-11-19 の判断）。理由：
  - 320×568 では、タイルの下端（684px）と帯の上端（497px）の差が約190px あり、文字を縮めずに詰めるには、見出し下の「約束」か緊急の案内の説明を最初の画面から外すしかない。どちらも先に決めた骨格なので外さない。
  - WCAG は「最初の画面に収める」ことを求めていない。求めているのは、隠れずに操作できること（2.4.11）と、横にはみ出さないこと（1.4.10）。そこで第3弾では、この2つを測って直した。
    - 「すぐ閉じる」が幅320px で2行に折れて帯が 91px になり、キーボードで動かしたときに部品が帯に隠れていた（320×568 で 29 か所中 3、文字1.25倍で 5）。ボタンを1行に保ち、帯の分の余白を文字の大きさに合わせた（`scroll-padding-bottom: calc(5.5rem + 16px)`）。直した後は、320×568（等倍・1.25倍・1.5倍）と 390×664（1.25倍・1.5倍）で 0。文字の拡大は、ページの基準の文字の大きさ（html）を 20px・24px にして模した。
    - 文字を大きくしたときに、文節で改行する見出しや選択肢が欄からはみ出していた（例：支える人への「親が家賃…」は 文字1.25倍・幅320px で 23px）。`overflow-wrap: anywhere` を足し、文節が欄より長いときだけ文節の中で折り返すようにした。通常の文字の大きさでは、全ページの画面が変える前と1画素も変わらないことを確かめた（390・320・1024px）。
